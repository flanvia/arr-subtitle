# 누적 합본 및 Linux TLS 수정

## 범위

시즌 회차와 누적 회차를 출처별 증거로 연결하고 Linux NativeAOT에 OpenSSL을 정적으로 연결한다. 기존 JSON 및 검색 수정은 보존한다. 시스템 OpenSSL 교체, 인증서 검증 비활성화 및 사설망 접근 허용은 하지 않는다.

## 누적 회차

Anissia caption의 회차와 해당 게시물 제목 및 단일 회차 첨부 이름이 일관되게 대응할 때 오프셋을 확인한다. 예를 들어 2기 caption 12화의 게시물이 24화이고 개별 첨부도 24화면 누적 오프셋 12다. 합본의 최댓값이나 시즌 번호만으로 오프셋을 추측하지 않는다.

2기 합본 1화부터 24화 중 13화부터 24화만 시즌 회차 1화부터 12화로 나열하고 원본 번호와 멤버 이름을 함께 보존한다. 앞 시즌 파일은 현재 시즌에 배정하지 않는다. 여러 seed의 대응이 충돌하면 명시 오류다. 사용자 명시 매핑은 검증된 범위에서 우선하며 검색과 실제 다운로드가 같은 변환기를 사용한다.

## Linux TLS

`StaticOpenSslLinking=true`로 Linux CLI와 smoke를 게시한다. 고정 OpenSSL 소스와 SHA-256을 검증해 빌드하며 `libssl.so`를 사용자 시스템에 설치하거나 배포하지 않는다. macOS와 Windows는 기존 OS TLS를 사용한다.

환경 변수와 사용자 OpenSSL 3 없이 NativeAOT에서 실제 HTTPS를 검증한다. CI는 Linux 컨테이너의 OpenSSL 4 환경도 검증한다. OpenSSL 라이선스를 배포물에 포함하고 버전 및 재배포 갱신 책임을 기록한다.

## 확인한 실제 결과

여친, 빌리겠습니다 2기의 caption 12화, 제작자 글 24화 및 개별 첨부 24화로 오프셋 12를 확인했다. 검색은 누적 13화부터 24화를 시즌 1화부터 12화로 표시한다. 실제 `collect`에서 시즌 1화는 `KNKR 13.smi`, 시즌 12화는 `KNKR 24.smi`를 받아 저장하고 해시를 검증했다. 출력 경로는 시즌 회차를 사용한다.

같은 검증을 OpenSSL 4만 있는 로컬 환경에서 `LD_LIBRARY_PATH` 없이 수행했다. 시스템 libssl 또는 libcrypto의 동적 의존성은 없으며 OS CA 인증서 검증은 유지한다. glibc 및 ICU까지 정적으로 포함한 것은 아니다.

처음 최소 Fedora 컨테이너는 ICU가 없어 smoke 시작에 실패했다. ICU와 CA 인증서를 준비한 환경에서 실제 HTTPS와 인증서 검증이 통과했다. 해당 컨테이너의 OpenSSL은 4.0.3이며 `libssl.so.3`은 없다. 이를 libssl 문제로 숨기거나 globalization을 끄지 않았다.

## 리뷰 및 검증

- 번호 변환은 플랫폼, 블로그 식별자와 카테고리로 격리한다.
- 같은 출처의 caption 변환이 충돌하면 기존 변환과 검색 목록을 무효화한다.
- 다운로드는 저장 전에 관련 caption seed를 모두 확인한다.
- 사용자 명시 오프셋은 한 번만 적용하고 검색과 다운로드에 같은 모델을 사용한다.
- 자동 근거가 없는 뒤 시즌의 누적 ZIP은 현재 시즌의 같은 번호로 저장하지 않는다.
- 테스트 118개 통과. 정적 NativeAOT와 실제 누적 합본 다운로드를 검증했다.
- 버전과 checksum을 고정한 OpenSSL 빌드 스크립트의 정적 라이브러리 및 라이선스 생성 확인.
- 새로 바뀐 Linux ARM64 CI 구성은 아직 원격 실행하지 않았다. 기존 6개 대상 CI의 성공과 이번 정적 TLS 변경 검증은 구분한다.

사용자가 커밋, push와 Release를 승인하여 기존 검색 및 JSON 수정을 포함한 `v0.1.1`을 준비한다. 원격 CI 완료 전에는 새 ARM64 TLS 구성이 통과했다고 주장하지 않는다. 포함 OpenSSL의 보안 업데이트는 새 바이너리 재배포가 필요하다.

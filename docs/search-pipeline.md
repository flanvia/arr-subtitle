# 검색 모듈 책임 분리

## 목적

사용자 요청은 검색 모듈을 일반적인 입력 처리 흐름으로 다시 구성하는 것이다. 작품명, 제작자 약칭, 릴리즈 그룹 및 공지 단어 목록을 검색 조정 코드에 추가하는 방식은 중단한다. 현재 로컬 수정은 보존한다.

## 구조

- `SubtitleSearch`: 전체 timeout, 단계 호출과 최종 보고서만 조정한다.
- `SearchCatalog`: 검색 후보를 선택하고 메타데이터를 읽는다.
- `SearchDiscovery`: caption에서 출처와 검증된 제목 및 번호 근거를 수집한다.
- `SearchSources`: 중복 없는 출처 실행, 동시성, 시간 예산과 탐색 완료 상태를 관리한다.
- `PostResolver`: 게시물과 첨부를 받아 회차별 관측 결과를 만든다. 플랫폼 판별 및 ZIP 파싱을 하지 않는다.
- `AttachmentInspector`: 링크 메타데이터와 응답 내용으로 단일 자막 및 ZIP을 구분한다. ZIP 멤버 검증과 단일 무회차 파일의 회차 상속을 담당한다.
- `EpisodeParser`: 제목과 파일명의 회차 표현을 파싱한다. 작품명에 포함된 숫자는 먼저 분리하며 릴리즈 그룹 이름별 분기를 두지 않는다.
- `SearchState`: 원본 출처, 실패와 발견 결과를 보존하고 번호 매핑 및 누락을 집계한다.

파일만 나누고 분기를 옮기는 것은 완료로 보지 않는다. 출처의 제목 근거, 회차 근거와 첨부 형태를 타입으로 전달한다. 알려진 작품 번호, 제목 및 그룹명에 의존한 조건은 검색 경로에서 제거한다.

## 판정 규칙

파일 확장자와 응답 내용은 별개다. Drive라고 ZIP으로 간주하지 않는다. 압축에 회차 없는 자막 하나만 있으면 게시물 또는 caption의 유일한 회차를 상속한다. 여러 회차에 단일 무회차 파일을 임의 배정하지 않는다.

첨부가 없고 회차 근거도 없는 게시물은 검색 결과가 아니다. 첨부 없는 명시 회차 게시물 또는 caption은 첨부 누락이다. 공지나 후기라는 문자열의 존재로 판정을 바꾸지 않는다.

본문 재조회 뒤 제목과 회차를 다시 판정한다. 원본 제목, 게시물 및 첨부별 시즌 충돌은 유지한다. 차단, 삭제 및 불완전 페이지 순회를 성공으로 처리하지 않는다.

- [x] 결과 상태와 근거 수집 분리
- [x] 검색 단계 분리 및 조정 코드 축소
- [x] 단일 Drive 자막, 무회차 ZIP, 실제 누락 및 공지의 데이터 기반 검증
- [x] 전체 회귀 테스트와 NativeAOT 및 실제 검색

상시 DB, 플러그인 로더와 새 설정 체계는 추가하지 않는다. 기존 보안 제한, 공개 CLI 계약과 source-generated JSON을 유지한다.

## 검증 기록

- 공통 회차 파서 및 일반 첨부 처리 테스트를 포함한 전체 테스트 147개 통과.
- 별도 리뷰에서 Important 8건을 확인하고 수정했다. 작품별 예외나 릴리즈 그룹 목록은 추가하지 않았다.
- Linux x64 CLI와 smoke 실행기를 NativeAOT로 게시했다. 동적 의존성은 libc와 libm이며 libssl 및 libcrypto는 없다.
- 환경 변수 없이 직접 다운로드, 합본 다운로드, 미발견, 전체 검색, 취소 smoke를 통과했다.
- 호스트와 Fedora 45 컨테이너에서 HTTPS 인증서 검증을 통과했다.
- 실제 `마법소녀를 동경해서` 검색은 작품 2744만 선택하고 1~13화의 두 첨부 버전을 보존했다. 네이버 출처 실패로 전체 결과는 미완료다.
- 실제 `흉란영애` 검색은 작품 3433의 1~5화를 찾았고 전체 탐색을 완료했다.
- 실제 `Working` 검색은 부분 결과를 보존했다. 접근 실패와 첨부 누락을 명시하며 전체 성공으로 처리하지 않았다.
- 실제 `여친, 빌리겠습니다 2기` 검색은 누적 13~24화를 시즌 1~12화로 변환하고 원본 번호와 근거를 보존했다. 출처 일부의 탐색 실패는 미완료로 남겼다.
- 작품 1975의 1화와 12화를 새 디렉터리에 다운로드했다. `KNKR 13.smi`와 `KNKR 24.smi`가 선택됐으며 저장 파일의 SHA-256이 보고서와 일치한다.
- 초기에는 `StaticSslLibs`만 확인해 실제 링커 수정 여부를 잘못 판단했다. 리뷰에서 `LinkerArg`가 이미 복사된 것을 확인했다. 최종 `LinkerArg`에서 `-lssl -lcrypto`를 제거하고 지정한 prefix의 아카이브 절대 경로를 사용하는 것을 검증했다.

## 리뷰 수정

- 정확한 후보가 없을 때도 구두점으로 구별되는 제목을 다른 시즌에 연결하지 않는다.
- 게시물 제목이 맞는다는 이유만으로 첨부 이름을 전부 별칭으로 승격하지 않는다. 카테고리 이름의 정확한 대응 또는 유일한 누적 번호 대응 근거를 요구한다.
- 본문을 재조회한 뒤 작품 근거를 다시 검사한다.
- 게시물에 명시된 회차를 기대 범위로 기록한다. 부분 합본의 마지막 누락과 단일 회차 충돌을 숨기지 않는다.
- 단독 지정 회차 작품은 해당 회차 범위만 누락 집계에 사용한다.
- 숫자 작품명, 해상도 토큰과 연속된 `SxxExxExx` 회차를 공통 파서로 처리한다.
- 다운로드 응답의 실제 파일명도 회차 근거로 사용하고 표시 이름과의 충돌을 거부한다.
- 실제 링커 인자에서 고정 OpenSSL 아카이브를 지정한다.

별도 리뷰의 경미한 지적은 없었다. Linux ARM64를 포함한 나머지 대상의 최신 검증은 원격 CI로 확인한다.

## 실행 판단

- 기존 미커밋 재작성 작업을 현재 작업 디렉터리에서 이어간다. 중간에 별도 worktree로 이동해 변경을 복제하지 않는다.
- 전역 작업 지침에 따라 구현을 먼저 마치고 전체 테스트와 리뷰로 검증한다. 이미 작성한 코드를 TDD 순서에 맞추기 위해 삭제하지 않는다.
- 기존 실패 태그는 강제로 옮기지 않는다. 배포는 검증된 새 커밋을 기준으로 처리한다.
- 부분 검색의 구두점 경계는 특정 작품명이 아닌 Unicode 문장부호 범주로 판정한다. 검색어가 문장부호로 끝나지 않으면 기존 부분 검색을 유지한다.
- 게시물 제목만으로 다른 이름의 첨부를 승인하지 않는다. 검증할 수 없는 제작자 약칭은 거부될 수 있으며 명시 매핑 또는 메타데이터가 필요하다.
- 하나의 명시 회차와 하나의 첨부 회차가 충돌하면 거부한다. 여러 회차를 실제 포함한 합본은 게시물의 대표 회차와 다를 수 있으므로 실제 멤버 회차를 유지한다.
